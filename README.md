# 第一人称恐怖视频 Skill

`first-person-horror-video` 是一套供 Codex 使用的制作流程：从一个想法或现成剧本出发，完成主观视角剧本自检、ChatGPT 网页设定图、全片分镜提示词、生成反馈修订和成片复盘。

**默认分工：Codex 制作与修订交付材料；你在火山剧创手动上传、绑定素材、提交提示词并生成视频。** 你可以从新故事开始，也可以直接带着失败镜头继续修改。

## 能做什么

- 自动选择标准模式或创作模式，检查因果、空间、时长和第一人称可拍性。
- 为人物、场景、道具和必要的变化形态建立稳定名称、图片文件和上传清单。
- 在设定图确认后，一次性交付全片分镜表及逐镜可复制提示词。
- 记录每镜的素材用途、首尾状态、连续动作、环境声和针对性约束。
- 根据视频、截图、时间点或文字反馈局部修改，保留旧版提示词。
- 把项目经验整理成复盘；经你审核后，再更新 skill 中的通用指导。

## 安装

### 方法一：让 Codex 安装

在 Codex 中发送：

```text
使用 $skill-installer，从这个 GitHub 目录安装 first-person-horror-video：
https://github.com/tyh3126710751-code/first-person-horror-video/tree/main/first-person-horror-video
```

安装后在下一轮消息中使用它。若未出现，重新打开任务或重启 Codex。若已有同名 skill，先保留本地修改，再让 Codex 对比并更新现有版本，避免安装两份同名目录。

### 方法二：下载并复制目录

1. 在仓库点击 **Code → Download ZIP**，解压。
2. 复制其中的 `first-person-horror-video/` 文件夹，保留 `SKILL.md`、`agents/` 和 `references/` 的层级。
3. 放到 Codex 能发现的技能目录。当前官方文档列出的个人目录是 `~/.agents/skills/`，项目目录是 `.agents/skills/`；已有环境若使用 `~/.codex/skills/`，沿用该环境实际目录或交给 `$skill-installer` 处理。
4. 确认技能列表中出现“第一人称恐怖视频”。

Windows 的个人目录可写为 `%USERPROFILE%\.agents\skills\first-person-horror-video\SKILL.md`。不要把仓库最外层和技能目录重复嵌套一层。

安装与发现机制参考 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。本仓库发布的是技能目录，未配置插件市场安装包。

## 使用前准备

- 使用支持本地 skill、文件读写的 Codex 环境，并选定保存作品的项目目录。
- 设定图流程需要可用的浏览器操作能力，以及已登录、可生成图片的 ChatGPT 网页。仅安装此 skill 不会增加浏览器工具或账户权限。
- 准备火山剧创账户，由你完成平台上的上传、绑定和视频生成。可用模型、参数与费用以你的当前页面为准。
- 有现成剧本、参考图、旧提示词或失败视频时直接提供，不必重新起稿。

网页生图或下载受阻时，Codex 会保存提示词和阻塞状态；只有实际取得的图片才标记为“已生成”。

## 快速开始

### 1. 逃跑与脱险故事

```text
使用 $first-person-horror-video。
在当前项目目录做一个约80秒、4:3的第一人称恐怖视频。
想法：我在医院侧楼值夜班，听到身后的脚步，必须找到出口，最后成功脱险。
无台词、无字幕、无配乐，保留环境声。
先写剧本并完成自检，等我确认后制作设定图。
我会在火山剧创手动上传素材和生成视频。
```

这类故事自动采用**标准模式**。起稿节奏参考：进入故事 → 恐怖积累并产生逃跑意图 → 受阻逃跑 → 脱险后放松、确认安全。各段可调整；例如 8＋34＋20＋18＝80 秒，结尾有安静收束。

### 2. 不需要逃跑的恐怖故事

```text
使用 $first-person-horror-video，采用创作模式，时长60秒。
故事：我躺在床上，时钟始终停在04:44；衣柜中的人每次眨眼都更近一点。
结尾保持悬疑，不安排成功逃跑。
保持主角双眼视角，先完善剧本并自检。
```

**创作模式**保留你指定的情节和结局，不强加脱险分段。封闭空间、无法脱身或留白故事也适用；同样检查主观视角、因果、空间和动作时长。

### 3. 从现成剧本继续

```text
使用 $first-person-horror-video。
读取项目里的剧本和00_项目状态.md，检查因果、空间、总时长与双眼视角。
保留已确认的剧情和结局，只改必须修改的地方。
```

你可以覆盖默认值：**约 80 秒、4:3、无台词、无字幕、无配乐**。画幅、时长、台词和声音需求最好在起稿时说明；后续变化会同步相关交付物。

## 制作过程与审核

| 阶段 | Codex 交付 | 你要做的事 |
| --- | --- | --- |
| 剧本 | 平台上传文本、自检结论、模式与时长 | 确认剧情及结局；上传后反馈解析偏差 |
| 设定图 | 实际图片、稳定名称、一句介绍、上传清单 | 确认图组，手动上传并报告实际名称 |
| 全片分镜 | 全片骨架、逐镜提示词、素材对应表 | 核对素材绑定及参数，粘贴并生成 |
| 局部修订 | 问题定位、新旧版本、修订记录 | 提供生成结果，验收新版 |
| 成片复盘 | 作品总结和拟写入 skill 的经验 | 审核哪些经验可以进入 skill |

新项目默认在**剧本**和**设定图**两个节点等待确认。设定图确认后先交全片提示词，再逐镜修订；不用每写一镜就暂停审核。已有成果沿用，直接修单镜也不必重走整个流程。

每镜提示词按“画风 → 素材引用 → 画面描写 → 连续动作 → 强约束”组织。主角双眼是唯一机位；手、袖口、腿脚可以自然入画，避免外部机位拍主角背影或全身。

## 在剧创中使用提示词

1. 按上传清单给素材命名，把正确图片加入对应分镜。
2. 将平台实际名称反馈给 Codex，核对提示词中的人物、场景和道具对应关系。
3. 粘贴该镜的**纯文本正文**；包外说明和 Markdown 代码围栏不用一起粘贴。
4. 核对名称关联、时长、输出画幅、生成模式和参考图，再自行生成。
5. 保存提示词版本与生成结果的对应关系，避免把当前编辑器文本当成旧视频生成时的文本。

“图片已下载”“图片已确认”“已上传”“已绑定”和“视频已验收”是不同状态。待核实的绑定会明确标注，不会虚构已生效的素材引用。

首尾帧默认用**文字状态**记录。衔接困难或需要平台首尾帧模式时才制作实际帧图；有已采用的视频时，也可评估其真实尾帧作为下一镜参考，并记录来源、版本和取帧时间。参考图与专门的首尾帧模式分别记录，不能保证逐像素延续。

平台操作与格式参考 [火山剧创官方文档](https://docs.volcengine.com/docs/drama-creation/short-play-creation?lang=zh)及你的实际编辑器。

## 怎样反馈效果更好

```text
使用 $first-person-horror-video，只修SH03。
旧提示词：项目文件中的SH03 v2。
视频：附上的SH03_v2.mp4。
问题：00:03手指按到4键，00:04却只有7键发光；目标是按7键后7键才亮。
实际绑定：P01_电梯面板_v1；模型、时长、画幅见附图。
保留旧版，检查接触动作和素材对应关系，再给我可复制的v3。
```

修订记录采用“**现象 → 证据 → 原因判断 → 局部改动 → 结果**”。只有截图或文字时，完整动作、声音和历史生成参数仍可能待核实；改了提示词也不代表新视频已经生成。

当前版本加强了姿态与视场、渐进显露、手与机关的接触链、门的闭合轨迹、相邻镜衔接和平台文本回读。它们用于减少提示词中的矛盾；具体视频效果需要通过生成结果验收。
